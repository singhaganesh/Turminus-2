The sieve CLI on this bench is `/app/bin/peatwick`. Drive it with `kindle`: it must treat `/app/livefold` as the live tree, compare that tree to the newest snapshot directory under `/app/snapurn/seals`, rebuild `/app/inkvat/sieve.bin`, and drop `/app/inkvat/pick.json` from the coverage cards in `/app/lutcards`. The mill pieces that have to agree with the CLI the verifier reruns are named in `/app/fieldnotes/LAYOUT.txt`. Source repairs under `/app` are required. Manual ledger writes are not enough; `kindle` must mint `/app/inkvat/pick.json` and `/app/inkvat/sieve.bin`. The verifier reruns `/app/bin/peatwick kindle`.

Symptom: edits that exist only as unsaved files on the desk still report an unchanged tree, and `kindle` comes back with zero rows. Every relative path whose on-disk bytes differ from the newest snapshot must show up as `live:<relpath>`. For each such token, pull every `ASSAY` attached to that relative path on a card. `pick.json` must be `{"rows":[{"path":"live:<relpath>","assays":["..."]}]}` and the assay list on each row is sorted. Rows omit paths that have no `ASSAY`. If the desk does not match the newest snapshot and `rows` is empty, `kindle` exits with a non-zero status. A desk that already matches the newest snapshot may keep an empty `rows` list and still exit 0. `path` is a string. Each assays entry is a string.

Cards begin with `REL` then list `ASSAY` names. `sieve.bin` records concatenate as: uint16be length, UTF-8 `live:` token, uint16be count, then that many uint16be-length assay names.
