The holdtrace utility captures lane bench activity as compact binary traces. Field definitions are centralized in `/app/tracekit/schema/span.json`. `/app/bin/holdtrace forge` rebuilds the Python emit/consume pair in `/app/tracekit/runtime/` and refreshes bundled regression traces. Use `/app/bin/holdtrace record --lane <id> --event <name> --grams <n> --out <path>` to capture a fresh trace; `/app/bin/holdtrace decode <path>` emits a single JSON line. Graded record output is written to `/tmp/holdtrace_grade.trc`.

Operators report that `/app/archive/deployed/lane_ops.trc` no longer decodes after the span revision, even though `/app/tracekit/smoke/corpus_len.py` still returns success. That archive line must read back as event `lane_open`, lane `7`, and `1250` grams. Captures made after forge must survive a decode pass unchanged. Bytes written by the emitter and accepted by the consumer must share the same four-character magic on newly generated traces.

JSON output carries `event`, `lane_id`, and `grams` as string/integer fields. On-disk layout rules are in `/app/tracekit/notes/wire.txt`; forge repair paths are in `/app/tracekit/notes/layout.txt`. Malformed input yields `{"error":"bad_trace"}` on stdout with a non-zero exit status. Correct the forge sources named in layout notes so regeneration produces working runtime modules; hand-edited runtime files or static trace rewrites are not sufficient. Run `/app/bin/holdtrace forge` after source fixes. The verifier reruns `/app/bin/holdtrace decode` on the archive, corpus samples, and `/tmp/holdtrace_grade.trc` without invoking forge again.
